# 交接资料说明

采购请求按 `request` 标识，`station` 是领料货位。外部单行按 `po_line` 标识，分段归属用 `requested_units`。确认表 `revision` 是同一外部单行的业务修订序号，转发人不是身份的一部分。请求状态 `timeout` 仅表示连接器未见回执。收货变动以 `receipt` 和 `revision` 定位，`available` 是已验收入位且可领的状态，`hold` 是隔离。调拨 `in_transit` 已获确认但尚未入位。班组需求用 `pick`、`station`、`sku` 定位行，`priority` 数字越小越优先，同优先级按 `due`，再按单号排序。领用记录中的 `issue` 是历史交接号，退回按 `pick` 与货位明细记账。各文件的 `arrival` 是接收批次序数，同一序数中的记录一起可见。数量是非负整数件数，时刻为 UTC。采购请求数量表示目标填补量，欠交指已确认仍未形成合格收货的余量；已确认但尚未送达和已经发起、结果未知的采购余量不能再次下采购请求。明确拒收或取消且没有其他有效保障的缺量才可建议补单。同一外部行服务多个请求时，收货可用量可供货位使用，而采购销欠按供应方确认的请求归属与分配顺序执行，购买表同一行按请求号升序消化已合格未隔离的收货。

字段 `arrival` 为合成交接批号，同号记录属于同次接收。没有批号的文件为该批资料采用的固定目录。

- `requests.csv`
- `purchase.csv`
- `receipts.csv`
- `transfers.csv`
- `picks.csv`
- `pick_receipts.csv`
